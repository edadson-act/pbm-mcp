Architecture · pbm-mcp v0.1.0

pbm-mcp: Pharmacy Benefit APIs as MCP tools

A localhost FastMCP server that turns twelve PBM GraphQL/OpenAPI specs into namespaced, allowlisted tools, and calls the upstream APIs with per-domain credentials.

Level 1 · System context

L1 — Who talks to pbm-mcp

One MCP client, one local server, twelve upstream domains. pbm-mock swaps in for the live hosts during development.

Mount rule

A domain mounts only when complete

  • Spec present in specs/<domain>/ and PBM_<DOMAIN>_BASE_URL set
  • Both OpenAPI and GraphQL in one domain → skipped
  • No spec → process still starts, zero tools

Upstream auth

Per-domain credential strategy

  • none, api-key, bearer-env, forward
  • forward copies the inbound MCP Authorization header
  • client-credentials is a slot only — domain skipped

Member data

Bodies never logged

  • Logs: domain, operation, status, latency
  • URLs suppressed (can carry member ids)
  • Errors truncated to 500 chars, secrets redacted

Level 2 · Components

L2 — Inside the server

Startup builds one sub-server per domain behind the allowlist gate; each tool call then flows left to right to the upstream API.

Allowlist gate

Deny by default

  • Missing / empty allowlist → zero tools
  • Mutations, non-GET routes, orderIdCard, saveConsent need write: true
  • Subscriptions never exposed

Request path

One tool call, end to end

  • Tool name {namespace}_{operation} routes to its sub-server
  • UpstreamGuard tags the operation for logs and sanitises errors
  • LoggingTransport times every upstream request

Startup skips

Logged, never fatal

  • no_spec, no_base_url, both_openapi_and_graphql
  • auth_not_implemented, auth_not_configured
  • invalid_spec on any loader exception
